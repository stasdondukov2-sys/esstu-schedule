# Участие в разработке

Создайте issue по шаблону ошибки или предложения, затем небольшую ветку и pull request. Для исправления данных укажите страницу официального портала и конкретную пару. Не публикуйте личные данные, токены и содержимое локального хранилища браузера.

## Локальная проверка

Нужны Python 3.11+ и Node.js 22.

```sh
pip install --require-hashes -r requirements-dev.txt
npm ci --ignore-scripts
ruff check .
ruff format --check .
pytest
npm run build:css
python -m scripts.build_static_site
npm run test:unit
npx playwright install chromium
npm run test:e2e
```

В Windows используйте PowerShell. Если пользовательский `ComSpec` указывает на несуществующий файл, задайте путь к штатному `cmd.exe` только в текущем процессе; системные настройки менять не требуется.

## Правила изменения данных

- Не подставляйте день, неделю, преподавателя или кабинет по предположению. Неизвестная структура должна оставаться явно неполной.
- `demo_data/` — сохранённые источники, а `tests/fixtures/` — независимые зафиксированные образцы. Изменение снимка не должно автоматически менять ожидаемый JSON теста.
- Для нового формата добавьте минимальный образец, ожидаемый результат и тест на повреждённую структуру. Для изменения golden-файла объясните каждое смысловое отличие в PR; сохраните SHA-256 исходного HTML.
- Сохраняйте происхождение данных, дату проверки и хеш. Сборка сайта не означает новую проверку портала.
- Публичный сервер не редактирует профили и не строит индекс аудиторий по HTTP-запросу.

## Интерфейс и PR

Проверьте мобильную ширину, светлую/тёмную тему, клавиатуру, закрытие диалога Escape и возврат фокуса. Декоративные SVG скрывайте от скринридера; кнопке без текста задавайте понятное имя. Пустой день, неполные данные и недоступный источник должны отличаться.

Опишите проблему, итоговое поведение, выполненные проверки и ограничения. Изменения интерфейса сопровождайте настоящим скриншотом. CI проверяет каждую ветку и PR; публикация выполняется только из main после успешных проверок.
