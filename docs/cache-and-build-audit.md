# Проверка кэша, CI и сборки — 16 октября 2026

Проверены `static/index.html`, `static/sw.js`, обновление worker в
`static/experience.js`, оба workflow и реализации `catalog.py`, `rooms.py`,
`teachers.py`, `scripts/build_static_site.py` в пакете проекта.

## Исправления

- Расписания загружаются из сети первыми. При недоступности сети или HTTP 5xx
  используется точная сохранённая копия с заголовком `X-ESSTU-Cache: offline`.
  HTTP 4xx не заменяется прежним успешным ответом. Параметры API-запроса входят
  в ключ: запрос одной группы не возвращает кэш другой.
- Оболочка берётся из версионного кэша установленного worker. Новая оболочка
  активируется кнопкой обновления; обработчик сообщения продлевает жизнь события
  до завершения `skipWaiting()`. Это уменьшает смешивание версий HTML, CSS и JS.
- Данные вынесены в отдельный постоянный кэш для области сайта. Обновление
  оболочки их не удаляет. При переходе со старого формата копируются только
  API-ответы этой области. Старые общие кэши оставлены: они могут принадлежать
  другому приложению на том же домене. Новые кэши очищаются только внутри своей
  области. Ошибка квоты не скрывает успешный ответ сети.
- Объединение преподавателей сохраняет разные группы, типы занятий и подгруппы
  даже при совпадении предмета и аудитории.
- Отсутствующие каталоги и файлы групп/кафедр учитываются в диагностике.
  Сборка не выдаёт время генерации за время проверки портала.
- Checkout не сохраняет токен в конфигурации Git. Поиск артефакта синхронизации
  читает все страницы истории: десять неудачных запусков больше не скрывают
  существующую успешную выгрузку. Отсутствие артефакта отмечается предупреждением.

## Подтверждённое устройство

- В workflow нет явных секретов. Для скачивания артефакта используется
  ограниченный `github.token`. Проверки имеют `contents: read`, `actions: read`;
  публикация — отдельные `pages: write`, `id-token: write`; уведомление —
  `issues: write`. Секреты не передаются в пользовательские команды.
- Cron `0 */3 * * *` задаёт запуск раз в три часа UTC. Это расписание, а не
  гарантия точного времени запуска GitHub. Неуспешная сборка не публикуется.
  Ошибка создаёт/обновляет один issue, восстановление закрывает его.
- `rooms.py` строит индекс только по известным полным расписаниям, сохраняет
  несколько записей одного слота и устраняет точные дубликаты. Сервер читает
  готовый файл; дорогое сканирование не выполняется по запросу пользователя.
- Каталог использует сохранённые страницы кафедр и дополняет их группами;
  происхождение и даты берутся из манифеста. Проверка структуры остаётся общей
  для сервера и статической сборки.

## Ограничения

- Отсутствие записи в индексе не доказывает физическую свободу аудитории.
  Неполные расписания исключены из индекса; весь портал не гарантирует полноту.
- Пропущенный файл группы отражён в статусе, но отдельного расписания у него
  нет: клиент должен показывать ошибку источника при HTTP 404.
- Разные написания списка групп могут дать отдельные записи; автоматическое
  объединение неоднозначных названий не выполняется.
- Проверки worker моделируют ошибки сети/хранилища и смену кэшей. Браузерные
  сценарии проверяют обычную загрузку и офлайн. Они не заменяют проверку
  конкретного установленного ярлыка на телефоне пользователя.
- Actions закреплены по основным версиям, а не по SHA коммитов.
