# Campus Glass 2.5.0 — изменения и проверка

Дата: 16 октября 2026. Проверяемая ревизия кода: [`4162ab60bac66133e63a3f36ababeaa8b06fd406`](https://github.com/stasdondukov2-sys/esstu-schedule/tree/4162ab60bac66133e63a3f36ababeaa8b06fd406). ## Сверка замечаний

- `0903ad2` предшествует публикации Campus Glass. В актуальной оболочке уже были description, тёмный фон `#10131d` и пустой профиль без имени реального преподавателя. Значение `app-version: 2.4.0` действительно оставалось старым: теперь HTML, experience.js, worker и сборщик согласованы на 2.5.0.
- Версия meta сама по себе не определяет обновление PWA. Сборщик добавляет к shell-кэшу метку каждой сборки. Обновление остаётся ручным через кнопку «Обновить», отдельный кэш данных `data-v1` сохраняется. API используют network-first с резервным чтением сохранённого ответа, а не постоянную cache-first выдачу расписания.
- Все runner закреплены на Ubuntu 24.04. Actions обновлены до выпусков с Node 24 и закреплены на полных SHA. Node приложения остаётся 22. Дата будущей миграции `ubuntu-latest` не нужна для работы закреплённой конфигурации.
- Оба workflow и полный worker включены в [публичный текстовый пакет](verification-inputs-2.5.0.txt); доступ к локальной папке не требуется. Пакет зафиксирован по ревизии кода выше, а не описывает произвольную будущую версию.

## Доказательства

Локальный проверенный результат на этой ревизии:

- Ruff: проверка кода и форматирования успешны, 51 Python-файл.
- Pytest: **56 passed, 36 subtests passed**.
- Девять групп JS-проверок успешны, включая совпадение расчёта недели Python/JS на 429 датах в трёх часовых поясах.
- Playwright: **37 passed, 1 skipped**. Пропуск относится к touch-жестам в desktop-проекте; тот же сценарий выполнен в mobile-проекте. После добавления утверждений о скрытии дневной ленты в режиме недели этот сценарий повторно прошёл на desktop и mobile.
- В настоящем Chromium проверено: установка worker → наполнение кэша → новая версия → кнопка обновления → сохранение данных → перезагрузка без сети. Это дополнение к изолированным тестам worker.
- Axe проверяет светлую/тёмную тему и поиск. Клавиатурные сценарии проверяют Escape, ограничение фокуса, возврат фокуса, отсутствие движения при клавиатурном открытии и reduced motion.

## Практические границы проверки

Эмуляция Chromium не подтверждает работу на конкретном физическом телефоне, в Safari или реальным скринридером. Данные портала могут быть неполными; предупреждения и неизвестная свежесть не скрыты. Отсутствие известной пары не означает физическую доступность аудитории. Схема корпусов условная и не изображает географию. Новая иконка — символ неофициального приложения, а не герб университета.

Первый успешный локальный запуск тестов не подменяет CI и фактическую публикацию: их следует сверять по статусам Actions и `api/status.json` опубликованного сайта. Старый ярлык с адресом корня `github.io/` нужно пересоздать с `/esstu-schedule/`; обновление worker не исправляет адрес чужого scope.
