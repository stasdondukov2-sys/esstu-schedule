## Публикация кода и данных

- Push/PR проверяют замороженные `demo_data`, прежде чем восстанавливать рабочие
  источники. Публиковать может только main. Ветка PR не меняет сайт.
- Постоянная ветка `data` хранит API и исходники. В отсутствие этой ветки первый
  main-запуск считывает полный API опубликованного Pages и проверяет, что
  публикация не сменилась во время чтения. Ошибка чтения останавливает выпуск.
  Обычный релиз интерфейса сохраняет предыдущие JSON; в status меняются только
  build_id, code_revision и отдельное code_deployed_at. Возраст данных сохраняется.
- Порог применяется только к обновлению данных: по умолчанию абсолютный предел
  25% и максимум +1 процентный пункт к прошлому набору. Прошлый API проверяется
  по тем же правилам названий, чтобы новое обнаружение заглушек не выглядело
  ухудшением реальных расписаний. Параметры ESSTU_MAX_PARSE_ERROR_RATE и
  ESSTU_MAX_PARSE_REGRESSION доступны явно. Прежний единый порог 5% отменён.
- Сбойная группа получает последний корректный JSON с тем же нормализованным
  названием, если дата проверки известна, не из будущего и не старше семи дней.
  Исходные дата, SHA и источник сохраняются, добавляются last_good_json,
  is_stale_fallback и причина. Файлы с заглушкой вместо названия не принимаются
  за другую группу. Неизвестная/истёкшая копия не продлевается.
- Новая версия портала проверяется по ETag/Last-Modified, размеру, SHA и имени
  группы до замены файла. Четыре запроса параллельно, два повтора с задержкой,
  повторный запуск переиспользует проверенные файлы моложе 25 минут. Ранее
  неудачные страницы запрашиваются снова. Неполная вся синхронизация не выдаётся
  за свежие данные: если ни одного источника не проверено, выпуск данных запрещён.
- Манифест сохраняется после каждой успешно проверенной страницы. После этапа
  загрузки (таймаут 8 минут) checkpoint сохраняет исходники в data, сохраняя
  предыдущий API, даже если последующая проверка новой выгрузки не пройдёт.
  Полное прекращение процесса/раннера до checkpoint не гарантирует сохранение
  последних незаписанных загрузок. Успешный API заменяется только после проверки.
- Артефакты диагностики остаются дополнительной копией, срок их хранения не
  определяет сохранность последнего API. После деплоя HTML и status.json
  сверяются с build_id той оболочки, на которой прошёл браузерный прогон.

## 121 случай: уточнение прежнего вывода

Прежняя формулировка «нужны пригодные исходники» была слишком общей. Проверены
все исходные 121 отказа: 86 — реальные несовпадения названия страницы с каталогом,
35 — заглушки каталога. У всех этих файлов есть цветной заголовок, нет нулевого
размера, присутствует закрытие HTML. Гипотеза об отсутствии #ff00ff не подтвердилась.
Имя теперь берётся из смыслового заголовка «Расписание занятий учебной группы:»,
а независимость от цвета закреплена тестом реальной страницы zo1/24.

Дополнительно выявлены 11 записей, где и страница, и каталог названы точками.
Раньше они проходили сравнение. Теперь результат — **132/663**: 86 несовпадений
и 46 заглушек. Это не 132 ошибки загрузки. Полный список с названиями, размерами,
SHA и причинами: [group-diagnostics-2026-10-17.json](group-diagnostics-2026-10-17.json).
Та же сводка и все записи включены в catalog-status.json, не только последние 50.

Caf48.htm содержит смешанную кодировку. Восстановление применяется только когда
строгая обратная перекодировка токена в UTF-8 успешна и сокращает текст; обычная
кириллица сохраняется. Реальная фикстура Caf48 проверяет полные таблицы и имена.
Новые HTML-фикстуры имеют отдельный manifest SHA; исходные файлы не правились.

Счётчики разделены: **73960 пустых**, **5445 требующих сверки**, **0 непустых
ячеек, потерянных целиком**. Последний показатель не доказывает правильность
каждого предмета: предупреждения сохраняют сырой текст для сверки. Старый
unparsed_cell_count оставлен совместимым как счётчик требующих сверки.
У 714 из 806 локальных источников дата неизвестна; она не выдумывается.

## Worker, время и интерфейс

- Через 3,5 секунды показывается копия с причиной refreshing, без отмены запроса.
  event.waitUntil удерживает загрузку; изменённый ответ сохраняется и вызывает
  DATA_UPDATED. Открытые расписание, каталог преподавателей и радар используют
  обновлённую копию. Реальный серверный тест задерживает ответ на 4,8 секунды,
  проверяет перерисовку без перезагрузки и последующий офлайн-запуск.
- Хеш включает нормализованный исходник sw.js, пути и байты всех ресурсов, но
  исключает api/. Генератор SHELL включает все локальные файлы, включая аватары.
  Тест проверяет ресурсы index.html и изменение хеша только от изменения worker.
- Лимит 200: FIFO для незащищённых адресов; текущая и избранные группы защищены
  (до 30 выборов/64 адресов). Настройки защиты сохраняются между запусками worker.
  Квота не скрывает сетевой ответ и не уничтожает предыдущую копию.
- Обновление оболочки перезагружает все ранее контролируемые вкладки, первая
  установка не перезагружает. Проверка видимой вкладки раз в 15 минут, явная
  кнопка с блокировкой и страховкой. Строгий CSP всего приложения не заявляется.
- Время кампуса получается через Intl.DateTimeFormat('Asia/Irkutsk'). Playwright
  в America/New_York проверяет 18.10 23:30 → I и 19.10 00:30 → II; отдельно
  сохранена проверка арифметики недели Python/JS на 429 датах.
- Обе пары с ФИО/а.701 и/п разбираются и индексируются. Сортировка/объединение
  строк радара, статус выбранного слота, предупреждения, один чип источника,
  компактный онлайн, диапазон соседних одинаковых онлайн-пар, русские склонения
  и нижний отступ сохраняют регрессионное покрытие.
- Светлая янтарная метка затемнена. Для пяти подписей в двух темах на desktop
  и mobile контраст измеряется по пикселям отрисованного фона; минимум 4,5 и
  размер 12px закреплены в CI. Это выборка, не доказательство всех фонов.
- Python >=3.11 объявлен явно; User-Agent — 2.5; Dependabot проверяет Actions и npm.
