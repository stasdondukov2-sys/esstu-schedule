## Дизайн по предоставленному HTML

Визуальная основа — пользовательский stealth_cyber_glass.html: фон #050507,
обсидиановое стекло, изумрудная текущая и фиолетовая следующая пара,
свечение точки, прогресс и компактная однострочная шапка. Демо-расписание
и панель с примером кода из референса не включены в приложение.

Состояния задаются при рендере и обновляются часами приложения. Переход
через конец пары снимает текущую подсветку; другой день не получает
ложные состояния «сейчас» и «следующая». Заметки прошедших пар доступны.
Сохранены предупреждения о качестве источника, светлая тема, клавиатура,
уменьшение движения и офлайн. Inter с кириллицей хранится локально,
лицензия OFL включена. SVG-иконки используют общий набор.

В шапке один h1 с названием группы, отдельные доступные имена поиска
и настроек. Исправления main включены без повреждённого sph1an и без
постобработки состояний через MutationObserver. CSS собирается из styles/.

Новые сценарии проверяют границы пары, таймер, прогресс, заметки и шапку
при 320 px. Существующие проверки контраста и axe выполняются в обеих темах.

## Выпуск и сохранность

- parser_revision учитывает код преобразования. При его изменении API
  перестраивается из сохранённых HTML без портала; даты проверки не меняются. Если кандидат не проходит порог, код всё равно публикуется с прежним API и явной причиной parser_rebuild_error.
  Локальная репетиция на опубликованных исходниках действительно пересобрала
  API: 0/663 ошибок обработки.
- Без ветки data восстанавливаются опубликованный API и только совпадающий
  по SHA артефакт исходников. Несовпадение останавливает выпуск.
- Контрактный smoke проверяет все группы и каталоги преподавателей/аудиторий.
  Четыре сценария desktop/mobile используют неизменённый старый API: группа
  и сведения, поиск, преподаватель, аудитории. Локально: 8 passed.
- Общий мягкий дедлайн sync — 360 с. Оставшиеся задания попадают в deferred;
  HTTP-чтение учитывает остаток времени. Жёсткий предел шага — 8 минут.
- Манифест фиксируется после каждого успеха. Артефакт прогресса загружается
  через always и подхватывается следующим sync: только main, более новые даты,
  совпадающие SHA. Это не заменяет постоянный API.
- Дефекты портала сохраняются отдельно в .negative с SHA, отпечатком каталога
  и датой, повторяются не чаще раза в сутки. Последняя хорошая страница
  не перезаписывается плохим ответом.
- Ветка data меняется только в persist-data после deploy и verify_deployment.
  Только этот job имеет contents: write; check читает репозиторий. Ручная
  репетиция не пишет data и Pages. Push только main устраняет двойные запуски.
- Cache v5 и download-artifact v8 работают на Node 24, SHA проверены.
  Ubuntu закреплена на 24.04. Оболочка нормализуется в LF; сырые CP1251 HTML
  и золотые HTML побайтово сохранены.

## Свежесть и worker

status содержит group_check_dates, число/долю проверенных за 24 часа групп
и 10-й процентиль. Монитор считает долю заново на момент проверки и сигналит
при <90%. Одна свежая страница не освежает весь набор.

Фон worker ограничен 60 секундами; копия отдаётся через 3,5 с без отмены фона.
Сравнение — ETag либо SHA-256, отпечаток сохраняется в кэше. Оболочка ограничена
5 MiB с тестом превышения. API — 200 ответов, FIFO среди незакреплённых;
текущие/избранные URL защищены PROTECT_DATA. 5xx и отсутствие сети различаются.

## Проверки и оставшиеся ограничения

Ruff и форматирование прошли. Python: 145 passed, 9 subtests passed в одном
полном прогоне. Playwright после нового дизайна: 75 passed, 1 skipped (из 76), один полный прогон. Пропущен сценарий мобильного свайпа в desktop-проекте; на телефоне он проходит. Полный браузерный журнал и поимённый список Python включены
в verification-inputs-current.txt. Локальные проверки не являются CI;
удалённые Checks и ручная репетиция указываются отдельными ссылками в PR.

Внешний монитор Cronitor создан после входа пользователя через Google. Период 3 часа, запас 1 час, Alerts On, список Default. HEALTHCHECK_URL сохранён в секрете репозитория; значение не входит в исходники. Проверено состояние Waiting for first event. Первый рабочий пинг ожидается после успешного деплоя main и проверки build_id; доставка аварийного уведомления ещё не проверена. Регистрация Healthchecks не завершилась из-за отсутствия писем на Mail.ru и Gmail.

Первая удалённая репетиция обнаружила HTTP 503 при bootstrap опубликованного API. Добавлены до пяти попыток с отступом для 408/429/5xx и сетевых сбоев, без повторов для 404; это покрыто отдельными тестами. Итоговая репетиция должна быть проверена в Checks нового коммита.

История data сохраняется целиком. Политика обслуживания: ежемесячная проверка
размера; перед ротацией — скачанный git bundle и проверка восстановления.
Автоматическая orphan/force-push ротация не включена, история не переписывалась.
Это оставшийся эксплуатационный пункт, не заявленное исправление.
