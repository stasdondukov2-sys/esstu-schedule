# P0: публичный сервер только для чтения

16 октября 2026. Выбран вариант полного удаления публичной записи вместо хранения административного токена в веб-интерфейсе.

1. `/api/teacher/meta` не имеет обработчика записи. Любой POST получает 405 без чтения тела и без изменения файлов. Preflight для POST также получает 405. CORS разрешает только GET; ответы POST не содержат Access-Control-Allow-Origin.
2. Форма изменения профиля удалена из сайта. Профили редактируются владельцем в `teachers_meta.json` и публикуются обычной сборкой. `photo` допускает только существующие локальные файлы `avatars/<ASCII-имя>.png`, `.jpg`, `.jpeg`, `.webp` в `static/`; проверяются путь и принадлежность каталогу. HTTP/HTTPS, data:, javascript:, абсолютные пути, обходы каталогов и SVG от пользователя не принимаются. Сервер не загружает изображения из сети. Для фотографии владелец добавляет проверенный файл в `static/avatars/` и относительный путь в JSON; общедоступной загрузки нет.
3. Если локальной фотографии нет, браузер генерирует SVG с инициалами. Эти SVG создаются из текста самим приложением, а не принимаются как photo. В JSON нет многократного копирования SVG на каждое занятие. Внешний ui-avatars.com не используется. Старые внешние photo из кэша также игнорируются. Атрибуты изображений и поля профиля экранируются, обработчики выбора используют индексы вместо строк из данных.
4. TLS использует системное доверенное хранилище: `ssl.create_default_context()`, `CERT_REQUIRED`, `check_hostname=True`. Совместимость `OP_LEGACY_SERVER_CONNECT`, если поддерживается Python, сохранена. Проверка цепочки не отключается; при ошибке сертификата остаётся явно помеченный резервный источник. Пиннинг отпечатка не нужен для выбранного варианта проверки доверенной цепочки.
5. POST обёрнут в обработку ошибок; Content-Length — неотрицательное десятичное число, предел 8192 байта (строже предложенных 64 КБ). Неверная, неоднозначная длина или Transfer-Encoding отклоняется с 400; обычный POST — с 405, независимо от JSON. Тело не читается, соединение закрывается. Проверка статики через resolve/is_relative_to уже действует и покрыта HTTP-тестом, включая соседний каталог static_evil.

Проверки: запрет POST и preflight, отсутствие CORS для записи, неправильные и большие длины, отсутствие вызова функции записи; вредоносные/внешние photo, обходы путей, старые URL; экранирование HTML, доверие TLS и проверка имени хоста. Проверки включены в CI. Они не заменяют защиту самого хостинга и репозитория.
